# Lab 任務：規則可調與重新計算

接在 `m1-m2-lab-task.md` 之後做，環境與限制相同（第 6 節的限制全部適用）。只需要 Rancher 所在叢集上的 server，以及至少一座有送資料的下游叢集。

## 1. 前提

- m1-m2 的 lab 已完成，server 有一段時間的資料。
- 本分支的映像檔已建置並推到 lab 用的 registry。

## 2. 步驟

1. **升級到本版、不改設定**：`helm upgrade` 只換映像檔。
   - 預期：「規則」頁出現 1 筆設定紀錄，沒有重新計算的提示。
   - 預期：舊資料的警示與「需要注意」跟升級前一樣（升級前後各截一張圖比對）。
2. **錯誤設定**：在 `server.rules` 寫一個沒有 `reason` 的例外，然後 `helm upgrade`。
   - 預期：新 Pod 起不來，log 第一行指出 `pod_exec.except[0]: reason is required`。
   - 預期：舊 Pod 繼續服務（rolling update 沒有完成）。
   - 改回正確設定。
3. **調整設定**：`pod_exec` 改為 `high`，例外 `namespaces: ["<某個測試 namespace>"]`；`secret_read` 關閉。
   - 預期：變更地圖與規則頁出現提示，筆數等於升級前的紀錄數，有預估時間。
4. **新紀錄用新設定**：在例外的 namespace 和另一個 namespace 各 exec 一次。
   - 預期：例外 namespace 的那次沒有警示，另一個是「高」。
   - 預期：之前的 exec 仍是「中」。
5. **權限**：用只有 `services/proxy` get 權限的帳號按「重新計算」。
   - 預期：畫面顯示沒有權限，伺服器沒有開始計算。
   - 順便確認 Rancher 經 service proxy 轉送 POST 時，`x-api-csrf` 標頭可以通過。若被 Rancher 擋下，記錄回應內容。
6. **重新計算**：用有 `create` 權限的帳號按「重新計算」。
   - 記錄：實際花費時間、預估時間、紀錄筆數。
   - 期間持續操作叢集，確認新紀錄照常進來，畫面照常可查。
   - 預期：完成後之前的 exec 變成「高」，例外 namespace 的消失，Secret 讀取的警示消失。
   - 預期：「收集狀態」頁的雜湊鏈驗證仍然完整。
7. **重新計算中重啟**：資料夠多時，在計算途中刪掉 server Pod。
   - 預期：新 Pod 起來後，規則頁該次顯示「因重啟中斷」。
   - 預期：判斷維持原狀，提示仍在。
8. **SIEM**：有設定轉送時，確認重新計算之前送出的事件沒有重送；之後的新事件帶新的判斷。

## 3. 回報

寫在 `docs/lab/report-rules.md`，格式比照 m1-m2 的報告：每一步的結果、截圖，以及第 6 步的實測速度（筆數／秒）。若實測速度跟預設值差很多，在報告中註明，以便調整 `rulestate.rs` 的 `DEFAULT_RATE`。
